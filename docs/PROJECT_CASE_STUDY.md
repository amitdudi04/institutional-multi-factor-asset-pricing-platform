# Project Case Study

## Problem

The prior repository had a valid two-security empirical publication but could not meet the fixed Phase 2 minimum cross-section of three. The challenge was to expand breadth without fabricating identity, shares, corporate actions, or fundamentals.

## Approach

The run screened all 822 HF candidates in a restart-safe cheap-to-expensive waterfall. Temporary provider throttling was retried and never counted as a rejection. Only 652 passed HF attribution and splice checks. SEC bulk evidence reduced the expensive parse set. Exact tagged 10-K contexts then established bounded symbol, class, exchange, and CIK evidence. A governed SEC projector made the final acceptance decision.

## Engineering findings

Real scale revealed three software defects: sparse Phase 3 formation dates invalidated later usable dates; sparse rolling windows aborted otherwise estimable regressions; and Phase 2 benchmark compounding incorrectly followed security-specific missing sessions. Each defect received a focused regression test and committed remediation. No analytical formula or owner threshold was relaxed.

## Outcome

The final universe has 487 equities. Real Phase 2 and Phase 3 passed. Phase 6 delivered the results. Phase 4 and Phase 5 correctly stopped at open governance decisions. The project demonstrates that fail-closed research engineering includes refusing to produce results when assumptions are not approved.
